# Testing

Run `python3 -m unittest discover -s tests -v` for sixteen local tests covering streaming, persistence, owner isolation, token denial, provider restrictions, configuration, deletion, retention, investigation evidence, policy proposals, apply/rollback/stale-file rejection, alert delivery, and the model tool protocol. The proposal tests use a fake verifier to confirm that staging does not change the active file. On a Wazuh host, run a candidate through native `verify-agent-conf` before applying it. Test the SSH rule with all three fixtures using native `wazuh-logtest` before manager restart.

Build the native plugin with esbuild 0.25.12. With `ESBUILD_PATH` set to that installation's JavaScript API, run `node tests/test_read_tools.js` to check source allowlists, argument bounds, and permission propagation. Run `node tests/test_chat_broker.js` to exercise a complete tool call, current-user search, audit record, and saved reply through a fake loopback model service. Run `node tests/test_policy_routes.js` to check administrator and agent-group gates before apply. The latter two tests require permission to bind local loopback ports.

On the test host, a loopback smoke test using the configured provider produced a `get_capabilities` call and a complete answer after the tool result, then produced a `search_alerts` call for a recent SSH-login question. This verifies provider tool support, not the authenticated Wazuh search path. The real Wazuh validator accepted a temporary test-group proposal; the apply service wrote and rolled back only that temporary group, while the active default group configuration stayed byte-identical. Check a real search and the UI in an operator-owned authenticated session without browser automation.
